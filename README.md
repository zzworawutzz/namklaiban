# น้ำใกล้บ้านฉัน

ดูระดับน้ำจากสถานีวัดที่ใกล้บ้านที่สุด ข้อมูลจาก ThaiWater (สสน.) ใช้ประกอบการตัดสินใจเท่านั้น ไม่ใช่ประกาศทางการ

| ไฟล์ | หน้าที่ |
|---|---|
| `ingest.py` | ดึงข้อมูล ThaiWater → ฐานข้อมูล, ลบข้อมูลเก่าเกิน 31 วัน, บันทึกผลการรัน |
| `db.py` | ชั้นเชื่อมต่อ: SQLite (ในเครื่อง/เทสต์) หรือ Postgres เมื่อมี `DATABASE_URL` |
| `core.py` | ตรรกะอ่านข้อมูล: stale, แนวโน้ม, เวลาถึงตลิ่ง, คำแนะนำ, ต้นน้ำ/ปลายน้ำ |
| `api.py` | FastAPI + endpoint `/api/cron/ingest` (ป้องกันด้วย `CRON_SECRET`) |
| `notify.py` | แจ้งเตือนเมื่อสถานะสถานีใกล้บ้านเปลี่ยน (LINE) |
| `public/` | หน้าเว็บ (Leaflet) + PWA (Vercel เสิร์ฟจาก CDN) |

## รันในเครื่อง
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python ingest.py
.venv/bin/uvicorn api:app --reload      # เปิด http://127.0.0.1:8000
.venv/bin/python -m pytest
```
ตั้ง cron ให้รัน `ingest.py` และ `notify.py run` ทุก 20 นาที

## API
`/health` · `/stations?province=&status=` · `/stations/nearby?lat=&lng=` · `/stations/{id}/readings?days=` · `/stations/{id}/related`

ฟิลด์เพิ่มของสถานี: `trend` (rising/falling/steady), `trend_pct_per_hr`, `eta_to_bank_h`, `advice`, `watch_pct`, `alert_pct`
- แนวโน้มคำนวณจากการวัดย้อนหลัง 6 ชม. ต้องมีข้อมูลห่างกันอย่างน้อย 45 นาที ถึงจะมีค่า
- `eta_to_bank_h` เป็นการต่อเส้นตรงจากอัตราปัจจุบัน ไม่ใช่การพยากรณ์
- `/related` แยกต้นน้ำ/ปลายน้ำจากระดับท้องน้ำของสถานีที่อยู่แม่น้ำเดียวกันในรัศมี 150 กม. เป็นการประมาณ

## Threshold ต่อสถานี
คัดลอก `thresholds.example.json` เป็น `thresholds.json` แล้วรัน `python ingest.py --thresholds thresholds.json` (ค่าเริ่มต้น 70% เฝ้าระวัง / 90% เตือนภัย)

## แจ้งเตือน LINE
1. สร้าง LINE Official Account เปิด Messaging API แล้วออก channel access token
2. `export LINE_CHANNEL_TOKEN=...`
3. `python notify.py add --channel line --target <LINE userId> --lat 14.2 --lng 99.0 --label บ้าน`
4. `python notify.py run` (ใส่ cron ต่อจาก ingest)

ลองโดยไม่ต้องมีบัญชีได้ด้วย `--channel stdout` แจ้งครั้งแรกเฉพาะเมื่อสถานีอยู่ที่เฝ้าระวัง/เตือนภัยแล้ว หลังจากนั้นแจ้งทุกครั้งที่สถานะเปลี่ยน

## แจ้งเตือนผ่าน LINE แบบให้ผู้ใช้สมัครเอง (webhook)
ผู้ใช้ส่ง **ตำแหน่งบ้าน** ให้บอตใน LINE (กด + → ตำแหน่งที่ตั้ง) ระบบเก็บ userId กับพิกัด แล้วแจ้งเตือนเมื่อสถานีใกล้บ้านเปลี่ยนสถานะ พิมพ์ "สถานะ" ดูค่าล่าสุด หรือ "ยกเลิก" เพื่อลบข้อมูล
ตั้งค่า:
1. env บน Vercel: `LINE_CHANNEL_TOKEN`, `LINE_CHANNEL_SECRET` (Basic settings ของ channel), ถ้าต้องการจำกัดจำนวนผู้ใช้ `MAX_SUBSCRIBERS` (ค่าเริ่มต้น 50)
2. LINE Developers → Messaging API → **Webhook URL** = `https://<โดเมน>/api/line/webhook` → Update → เปิด **Use webhook** → กด **Verify** ต้องได้ Success
3. ปิด **Auto-reply messages** และ **Greeting messages** ใน LINE Official Account Manager (ไม่งั้นข้อความซ้อนกับของระบบ)
ระบบตรวจ `X-Line-Signature` ทุกคำขอ จึงมีแต่ LINE ที่สมัครให้ผู้ใช้ได้ ควรมีหน้านโยบายความเป็นส่วนตัวก่อนเปิดให้คนทั่วไปใช้ เพราะเก็บตำแหน่งบ้าน

## รายงานสถานการณ์น้ำ
- **หน้าเว็บ** `/report.html?province=พระนครศรีอยุธยา` — ตัวเลขเตือนภัย/เฝ้าระวัง/ปกติ พร้อมการเปลี่ยนแปลงจาก 24 ชม. ก่อน, สถานีที่ล้นตลิ่งใหม่, กราฟจำนวนสถานีตามสถานะรายวัน, น้ำสูงสุด 10 อันดับ, สถานีที่ขึ้นเร็ว และปุ่มคัดลอกข้อความ/พิมพ์
- **API** `GET /reports/{จังหวัด}?days=14` (ชื่อจังหวัดตรงตัวตาม `/stations`)
- **สรุปทุกเช้า 07:00 (เวลาไทย) ทาง LINE** — ส่งให้ผู้สมัครที่ยังไม่ได้ปิด โดยใช้จังหวัดของสถานีที่ใกล้ตำแหน่งที่ส่งมา ระบบส่งวันละครั้งต่อคนในช่วง 07:00–10:59 (ตัวตั้งเวลา GitHub อาจช้าได้ จึงเผื่อช่วง ถ้าส่งไม่สำเร็จจะลองใหม่รอบถัดไป) ถ้าต้องการถี่ขึ้น ตั้ง env `DIGEST_EVERY_H` (เช่น 3 = 07:00, 10:00, 13:00, 16:00, 19:00 ไม่ส่งตั้งแต่ 22:00 กลุ่มแชตได้เฉพาะรอบ 07:00) ลองส่งทันทีด้วย `python notify.py digest` (ส่งได้เฉพาะในช่วงรอบสรุป)
- **บรรทัดเตือนฝนหนักในสรุปเช้า:** ถ้าพยากรณ์ฝน 24 ชม. ข้างหน้าของจังหวัดตั้งแต่ 35 มม. ขึ้นไป (ปรับด้วย env `RAIN_ALERT_MM`) สรุป 07:00 จะมีบรรทัด "🌧 พยากรณ์ฝน…" ต่อท้าย (`rainalert.py`) เรียก Open-Meteo ครั้งเดียวต่อจังหวัดที่มีผู้ติดตาม ใช้จุดกลางของสถานีในจังหวัด **ไม่ส่งตำแหน่งผู้ใช้ไปที่ไหน** ถ้าดึงพยากรณ์ไม่ได้ สรุปส่งตามปกติโดยไม่มีบรรทัดนี้ ไม่เพิ่มจำนวนข้อความ
- คำสั่งในแชต LINE: `รายงาน` ดูสรุปจังหวัดตอนนี้ · `ปิดสรุป` / `เปิดสรุป` · `สถานะ` · `ยกเลิก`
- ลิงก์ในข้อความใช้โดเมนจาก `VERCEL_PROJECT_PRODUCTION_URL` (Vercel ใส่ให้เอง) หรือกำหนดเองด้วย `PUBLIC_URL`
- **โควตาข้อความ LINE:** สรุปทุกเช้า = 1 ข้อความ/คน/วัน (~30/เดือน) รวมกับแจ้งเตือนเมื่อสถานะเปลี่ยน ถ้าตั้ง `DIGEST_EVERY_H=3` จะเป็น 5 ข้อความ/คน/วัน (~150/เดือน) ซึ่งอาจเกินเพดานของแผน LINE OA ตรวจเพดานข้อความของแผนที่ใช้ แล้วตั้ง `MAX_SUBSCRIBERS` ให้เหมาะสม
- กราฟย้อนหลังใช้ข้อมูลที่เก็บไว้ 31 วัน (วันที่ระบบยังไม่เคยเก็บจะว่างไว้) การเทียบกับเมื่อวานต้องมีประวัติครบ 24 ชม.

## แจ้งเตือนผู้ดูแลเมื่อดึงข้อมูลไม่ได้

ทุกรอบของ `/api/cron/ingest` ระบบตรวจ 2 อย่างแล้วส่ง LINE หาผู้ดูแล: (1) ดึงข้อมูลไม่สำเร็จต่อเนื่องเกิน 60 นาที (2) ดึงสำเร็จแต่ไม่มีสถานีไหนอัปเดตเกิน 6 ชั่วโมง ส่งครั้งแรกทันที เตือนซ้ำทุก 6 ชั่วโมงถ้ายังไม่หาย และแจ้งอีกครั้งเมื่อกลับมาปกติ (`watchdog.py`)

ระบบตรวจขนาดฐานข้อมูลทุกรอบด้วย ถ้าใช้เกิน 80% ของแพ็กเกจ จะส่ง LINE เตือนวันละครั้งจนกว่าจะลดลง (`watchdog.check_storage`) ตั้งขนาดแพ็กเกจด้วย env `DB_LIMIT_MB` (ค่าเริ่มต้น 512 = Neon ฟรี) โควตาการเรียกฟังก์ชันของ Vercel แอปอ่านเองไม่ได้ ให้ดูที่หน้า Usage ของ Vercel

**โควตาข้อความ LINE:** ทุก 6 ชม. ระบบถาม LINE เองว่าเดือนนี้ใช้ข้อความไปเท่าไรจากโควตา (`/v2/bot/message/quota`) ถ้าใช้เกิน 80% ส่งเตือนผู้ดูแลวันละครั้ง ถ้าแพ็กเกจไม่จำกัดจะไม่เตือน (`watchdog.check_line_quota`)

**กลุ่มสถานีที่เงียบพร้อมกัน:** เตือนผู้ดูแลเมื่อสถานีของหน่วยงานหนึ่งในจังหวัดหนึ่ง (อย่างน้อย 3 แห่ง) ไม่มีข้อมูลใหม่เกิน 6 ชม. ทั้งหมด หรือเมื่อหน่วยงานหนึ่งเงียบเกิน 25% ของสถานีทั้งหมด ขณะที่ส่วนอื่นยังปกติ แจ้งครั้งเดียวและแจ้งอีกครั้งเมื่อกลับมา (`watchdog.check_silent`) ถ้าทั้งระบบดึงข้อมูลไม่ได้ ตัวตรวจเดิมจะแจ้งแทน

**สถิติการส่งข้อความ:** ตาราง `send_log` เก็บ 60 วัน แต่ละแถวมีแค่เวลา ประเภท (status/early/fast/report/digest) จังหวัด และส่งสำเร็จหรือไม่ ไม่มี LINE ID ดูได้ที่ `GET /api/cron/stats?days=7` ด้วยรหัสเดียวกับ cron (`Authorization: Bearer ...`) ได้จำนวนต่อวัน ต่อประเภท ต่อจังหวัด จำนวนผู้ติดตาม ขนาดฐานข้อมูล โควตา LINE และกลุ่มสถานีที่เงียบ

**ทดสอบเกณฑ์เตือนน้ำขึ้นเร็วย้อนหลัง:** `python backtest_fast.py --db water.db` (หรือ `--api https://เว็บของคุณ --days 30` ซึ่งอ่านจาก API ของเราเอง ช้าเพราะเรียกทีละสถานี) จำลองว่ามีคนอยู่ติดสถานีละคน นับจำนวนข้อความที่จะถูกส่ง แยกส่วนที่เตือนล่วงหน้าเดิมส่งอยู่แล้ว ใช้ปรับ `FAST_RISE_M` / `FAST_MIN_PCT` ใน `notify.py` ไม่ส่งอะไรและไม่แก้ข้อมูล

**จำกัดการเรียกซ้ำ:** `ratelimit.py` จำกัดผู้เยี่ยมชมแต่ละรายไม่เกิน 240 ครั้งต่อนาทีที่ API (`/api/*`, `/stations*`, `/reports*`) เกินแล้วได้ 429 พร้อม `Retry-After` ตั้งเองด้วย env `RATE_LIMIT_PER_MIN` (0 = ปิด) ข้อจำกัด: บน Vercel แต่ละ instance มีหน่วยความจำของตัวเอง จึงเป็นการกันแบบ best-effort ไม่ใช่เพดานรวมที่เด็ดขาด ส่วนหนึ่งของภาระถูกดูดซับด้วยแคชของ CDN อยู่แล้ว ผู้ที่ใช้ Wi-Fi เดียวกันหลายคนใช้ที่อยู่เดียวกัน ถ้าถูกบล็อกบ่อยให้เพิ่มค่านี้ ไม่นับ `/health`, `/api/cron/*` และ `/api/line/webhook`

**สำรองข้อมูลผู้ติดตาม:** รายชื่อผู้ติดตาม LINE อยู่ในฐานข้อมูลที่เดียว รัน `DATABASE_URL="..." python backup_export.py` บนเครื่องของคุณ (สตริงเชื่อมต่อ Neon อยู่ใน Environment Variables ของโปรเจกต์ Vercel) ได้ไฟล์ `backup-วันที่.json` ที่เปิดอ่านได้เฉพาะคุณ ไม่อัปโหลดไปไหน และไม่พิมพ์ LINE ID ขึ้นจอ เก็บเป็นความลับและห้ามใส่ใน repo (`.gitignore` กันไว้แล้ว) กู้คืนด้วย `python backup_export.py --restore ไฟล์.json` ซึ่งเพิ่มเฉพาะรายที่ยังไม่มี รันซ้ำได้ ไม่ซ้ำซ้อน ระบบส่ง LINE เตือนผู้ดูแลทุก 30 วันให้ทำสำรอง (เริ่มนับ 30 วันหลังรอบแรกที่ระบบทำงาน) ปิดได้ด้วย `BACKUP_REMIND=0` ไม่สำรองข้อมูลระดับน้ำ เพราะเติมกลับจาก ThaiWater ได้ภายในวัน

**โครงสร้างหน้าเว็บ:** `public/index.html` เหลือเฉพาะโครงหน้ากับสคริปต์เล็กๆ ที่ต้องทำงานก่อน (เริ่มดึง `/stations` ทันที ซ่อนเบอร์ฉุกเฉินชั่วครู่ระหว่างโหลด) ส่วน CSS อยู่ที่ `public/app.css` และ JavaScript ที่ `public/app.js` ซึ่งเบราว์เซอร์แคชแยกกันได้ **กติกาเวลาแก้ไฟล์เหล่านี้:** ต้องเพิ่มเลขเวอร์ชันพร้อมกันสามที่ คือ `?v=` ของ `app.css` และ `app.js` ใน `index.html` และ `SHELL = "nkb-shell-vNN"` กับรายการไฟล์ใน `public/sw.js` มีเทสต์ (`test_pages.py`) ตรวจว่าตรงกัน ถ้าลืม เบราว์เซอร์ของผู้ใช้อาจค้างไฟล์เก่า

**เปิดซ้ำเร็ว:** service worker เปิดหน้าจากแคชทันทีแล้วอัปเดตเบื้องหลัง (ผลคือหลังอัปโหลดเวอร์ชันใหม่ ผู้ใช้จะเห็นเวอร์ชันใหม่ในการเปิดครั้งถัดไป ไม่ใช่ทันที) ส่วนข้อมูลสถานีไม่ผ่านแคชของ service worker แต่หน้าเว็บเก็บรายการสถานีล่าสุดที่โหลดสำเร็จไว้ในเครื่อง (Cache API ชื่อ `nkb-data`) ถ้าเน็ตช้าหรือหลุด จะแสดงชุดที่บันทึกไว้ก่อนพร้อมแถบบอกอายุ ("บันทึกเมื่อ 14:05 น. (45 นาทีก่อน)") ไม่เก่ากว่า 12 ชั่วโมง และแทนที่ด้วยข้อมูลใหม่ทันทีที่มา ถ้าเปิดครั้งแรกและเชื่อมต่อไม่ได้เลย ยังขึ้นแถบข้อผิดพลาดตามเดิม การเปิดแบบออฟไลน์เต็มรูปแบบ (ไลบรารีแผนที่จาก cdnjs) ยังไม่รองรับ

**เทสต์หน้าเว็บด้วยเบราว์เซอร์:** โฟลเดอร์ `e2e/` เปิดหน้าจริงใน Chromium บน API ที่ใช้ฐานข้อมูลทดสอบ แล้วตรวจพฤติกรรม (เรียงรายการ เทียบกราฟ กล่องศูนย์พักพิงและเบอร์โทร โหมดแบตต่ำ สีเส้นขอบ เบอร์ฉุกเฉินที่ต้องขึ้นเสมอ การแสดงข้อมูลที่บันทึกไว้ตอนเน็ตช้า/หลุด ฯลฯ) และจะล้มเหลวถ้าหน้าเว็บมี JavaScript error หรือถูก CSP บล็อก ไม่รวมใน `pytest` ปกติ รันเองด้วย `pip install playwright && playwright install chromium` แล้ว `E2E=1 python -m pytest e2e -q` (เพิ่ม `E2E_CHROME=1` เพื่อใช้ Chrome ในเครื่อง) ต้องต่ออินเทอร์เน็ต เพราะไลบรารีแผนที่มาจาก cdnjs GitHub รันให้อัตโนมัติด้วย `.github/workflows/e2e.yml`

**ตรวจเว็บจริงอัตโนมัติ:** `.github/workflows/smoke.yml` รอให้ Vercel deploy เสร็จหลังทุกครั้งที่อัปโหลด (และรันซ้ำวันละ 4 ครั้ง) แล้วเปิดหน้าเว็บจริงด้วยเบราว์เซอร์ ตรวจว่าแผนที่กับสรุปขึ้น ไม่มี JavaScript error หรือ CSP บล็อก `/health` ปกติ ถ้าพังงานจะล้มเหลวและ GitHub ส่งอีเมลหาเจ้าของ สคริปต์คือ `smoke_check.py` ลองรันเองได้ด้วย `pip install playwright` แล้ว `SMOKE_CHROME=1 python smoke_check.py` (ใช้ Chrome ในเครื่อง)

**น้ำขึ้นเร็ว:** `core.fast_risers` จัดอันดับสถานีที่ระดับน้ำ (เมตร) เพิ่มตั้งแต่ 0.30 ม. ใน 3 ชม. แม้ยังต่ำกว่าเกณฑ์เตือน ค่าที่กระโดดเกิน 2 ม. ระหว่างสองการอ่าน หรือเกิน 3 ม. รวมใน 3 ชม. ถือเป็นเซ็นเซอร์ผิดปกติและไม่นับ แสดงในการ์ดสถานการณ์บนเว็บ (`rise_3h_m` ใน `/stations`) และเป็นบรรทัด "น้ำขึ้นเร็วใน 3 ชม." ในสรุป LINE

หัวป้องกันความปลอดภัย (CSP, X-Frame-Options ฯลฯ) อยู่ใน `security.py` และมีสำเนาใน `vercel.json` โดยมีเทสต์ตรวจว่าตรงกัน ถ้าหน้าเว็บเรียกโฮสต์ภายนอกเพิ่ม ต้องเพิ่มใน `connect-src` ด้วย การเปิดหน้าเว็บด้วย `?api=` ที่ชี้ไปโฮสต์อื่นจะถูกบล็อก

ตั้งค่า: ส่งข้อความ `ไอดีของฉัน` ให้บอต แล้วนำค่าที่ได้ไปใส่ env `ADMIN_LINE_ID` ใน Vercel (ไม่ตั้ง = ไม่ส่งอะไร) ข้อจำกัด: ถ้าตัวตั้งเวลาหยุดเรียกทั้งหมด (เช่น GitHub ปิด schedule หลัง repo เงียบ 60 วัน) ระบบจะไม่มีรอบให้ตรวจ ให้ดูอีเมลแจ้ง workflow ล้มของ GitHub เป็นตัวสำรอง

## สถานีเตือนภัยน้ำป่า (DWR) — มี API แต่ปิดจากหน้าเว็บ

`GET /api/ews/warnings` (`ews.py`) ดึงสถานีเตือนภัยของกรมทรัพยากรน้ำ (`ews.dwr.go.th`) เก็บเฉพาะสถานีที่ DWR ตั้งสถานะ 1–3 แล้วแคช 10 นาที ใช้งานได้เมื่อเซิร์ฟเวอร์อยู่ในประเทศไทย แต่บน Vercel (สิงคโปร์) เชื่อมต่อ DWR ไม่ได้ (`Connection timed out` เพราะ DWR ไม่ตอบ IP ต่างประเทศ) และ DWR ไม่เปิด CORS ให้เบราว์เซอร์เรียกตรง จึงถอดชั้น "น้ำป่า" ออกจากแผนที่ ถ้ารันเองบนเซิร์ฟเวอร์ในไทย (เช่น Docker) endpoint นี้ใช้ได้ทันที และสามารถเพิ่มชั้นกลับได้ (ดู commit `ece652a`) ต้นทางตอบช้าราว 16 วินาทีต่อครั้ง และธงสถานะที่ค้างหลังเหตุการณ์ผ่านไปแล้วยังไม่รู้ความหมายชัดเจน จึงไม่ควรใช้ส่งแจ้งเตือน

## แผนที่
- **กดตรงไหนก็ได้บนแผนที่** เพื่อดู 3 สถานีที่ใกล้จุดนั้นที่สุด
- **ค้นหาสถานที่:** พิมพ์ชื่อตำบล/ตลาด/วัด แล้วกด Enter (ใช้ Nominatim ของ OpenStreetMap คำค้นจะถูกส่งไปยังบริการนั้น ใช้เฉพาะเมื่อกด Enter หรือกดแถว "ค้นหาเป็นชื่อสถานที่" ไม่ค้นระหว่างพิมพ์ ตามนโยบายการใช้งานของ OSM)
- **เส้นเชื่อมสถานีตามแม่น้ำ** จัดกลุ่มตามชื่อแม่น้ำ+ลุ่มน้ำ เรียงตามระดับท้องน้ำ (สูง=ต้นน้ำ) เชื่อมสถานีที่ห่างกันไม่เกิน 80 กม. สีตามสถานะที่แย่กว่าของสองปลาย เป็นเส้นตรงระหว่างสถานี **ไม่ใช่แนวแม่น้ำจริง** และการเรียงต้นน้ำ-ปลายน้ำเป็นการประมาณ

## ใช้งานบน LINE ให้สะดวกขึ้น
- **ข้อความแบบการ์ด (Flex):** แจ้งเตือน/สถานะ/สรุปเช้าส่งเป็นการ์ดสี พร้อมแถบระดับน้ำ แนวโน้ม และปุ่มเปิดรายงาน ทุกการ์ดส่งคู่กับข้อความธรรมดา ถ้า LINE ปฏิเสธการ์ด (HTTP 400) ระบบส่งข้อความธรรมดาแทนทันที จึงไม่มีทางที่การ์ดเสียทำให้แจ้งเตือนหาย
- **ตั้งค่าส่วนตัว** พิมพ์ `ตั้งค่า` จะมีปุ่มให้แตะ: `แจ้งทุกระดับ` / `แจ้งเฉพาะเตือนภัย` (เฉพาะตอนถึงหรือพ้นระดับเตือนภัย), `ไม่รบกวนกลางคืน` / `แจ้งกลางคืน` (22:00–06:00 ไม่ส่งยกเว้นเตือนภัย ข้อความที่ค้างส่งหลัง 06:00), `ปิดสรุป` / `เปิดสรุป` ส่งตำแหน่งใหม่ไม่ทำให้ค่าที่ตั้งไว้หาย
- **ใช้ในกลุ่ม/ห้องแชต LINE:** เพิ่มบอตเข้ากลุ่ม แล้วพิมพ์ `ติดตาม อยุธยา` (ชื่อจังหวัดบางส่วนได้ ถ้าตรงหลายจังหวัดบอตจะถามให้ชัดขึ้น) ทั้งกลุ่มจะได้สรุปจังหวัดนั้นทุกเช้า 07:00 คำสั่งอื่น `รายงาน` `ปิดสรุป` `เปิดสรุป` `ยกเลิก` `ช่วยเหลือ` บอตไม่ตอบแชตทั่วไปในกลุ่ม และลบข้อมูลกลุ่มเมื่อถูกเอาออกจากกลุ่ม กลุ่มได้เฉพาะสรุปเช้า ไม่ได้แจ้งเตือนเมื่อสถานะเปลี่ยน
- **Rich menu (ปุ่มใหญ่ใต้ช่องแชต):** ภาพกับนิยามอยู่ที่ `richmenu/` ตั้งบนบัญชี LINE OA ด้วยคำสั่งนี้ในเทอร์มินัลของคุณ (พิมพ์ token เอง สคริปต์ไม่แสดง token):
  ```bash
  export LINE_CHANNEL_TOKEN='...'
  .venv/bin/python richmenu/setup_richmenu.py --delete-old
  ```
  ปุ่ม: ส่งตำแหน่ง (เปิดหน้าแชร์ตำแหน่งของ LINE) · สถานะ · รายงาน · ตั้งค่า แก้ภาพได้ที่ `richmenu/make_image.py` (ใช้ฟอนต์ Krungthep ของ macOS เพราะ Pillow แบบพื้นฐานวางวรรณยุกต์ของ Thonburi ไม่ถูก)

## Deploy บน Vercel + Neon (Postgres)
1. push โปรเจกต์ขึ้น GitHub แล้ว Import ที่ Vercel (ไฟล์ `pyproject.toml` ชี้ entrypoint, `vercel.json` ตั้ง region `sin1`)
2. Vercel → Storage / Marketplace → เพิ่ม **Neon** ให้โปรเจกต์ จะได้ env `DATABASE_URL` มาเอง (ควรเป็น URL แบบ pooled) และเลือก region สิงคโปร์ให้ตรงกับฟังก์ชัน
3. ตั้ง env เพิ่มใน Vercel: `CRON_SECRET` (สตริงสุ่ม ≥16 ตัว) และถ้าจะแจ้งเตือน `LINE_CHANNEL_TOKEN`
4. Deploy แล้วตั้งตัวเรียก `/api/cron/ingest` ทุก 20 นาที เลือกอย่างใดอย่างหนึ่ง:
   - **ฟรี (Hobby):** Vercel Cron ฟรีรันได้วันละครั้ง และ expression ที่ถี่กว่านั้นทำให้ deploy ล้มเหลว จึงใช้ `.github/workflows/ingest.yml` แทน: ตั้ง repo secret `CRON_SECRET` (ค่าเดียวกับ Vercel) และ repo variable `APP_URL`
   - **ตัวตั้งเวลาภายนอก (เช่น cron-job.org) ซ้อนเป็นตัวสำรอง:** ตั้ง env `CRON_SECRET_EXTERNAL` (ค่าสุ่มแยกจาก `CRON_SECRET`) แล้วให้บริการนั้นเรียก `GET /api/cron/ingest` พร้อมหัว `Authorization: Bearer <ค่านั้น>` ทุก 20 นาที ลบ env นี้เพื่อเพิกถอนทันทีโดยไม่กระทบ GitHub (รันซ้อนกันได้ปลอดภัย: มีล็อกและข้อมูลไม่ซ้ำ)
   - **Pro:** เพิ่มใน `vercel.json` แล้ว Vercel จะส่ง `Authorization: Bearer $CRON_SECRET` ให้เอง
     ```json
     "crons": [{ "path": "/api/cron/ingest", "schedule": "*/20 * * * *" }]
     ```
5. เปิด `https://<โดเมน>/health` ดู `ingest_ok` ต้องเป็น `true` หลังรันรอบแรก

เพิ่มผู้รับแจ้งเตือน (รันจากเครื่องคุณ ชี้ DB ของ Neon):
```bash
DATABASE_URL='postgresql://...' .venv/bin/python notify.py add --channel line --target <userId> --lat 14.2 --lng 99.0 --label บ้าน
```
ข้อควรรู้: cron ส่งซ้ำหรือพลาดได้ (best effort) ระบบจึงออกแบบให้รันซ้ำได้ปลอดภัย (ข้อมูลไม่ซ้ำ + ล็อกกันรันซ้อน)
